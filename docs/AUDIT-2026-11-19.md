# Code audit — 2026-11-19

A third pass after 0.38.0, aimed at slow and unreliable connections and at
performance. Five areas were read by separate reviewers: the session and
network layer; the video pipeline; the desktop GUI; files, clipboard, sound
and tunnels; and the station with the Rust server and the client's directory
code. Every finding was checked against the code before it was fixed or
listed here. The [2026-11-05 audit](AUDIT-2026-11-05.md) lists earlier work.

Video on slow links was measured, not only read: `scripts/test-slow-link.py`
runs a host and a viewer in a private network namespace with emulated delay,
loss and bandwidth (netem), with a scrolling page of text on the host. The
software encoder, in frames a second (first picture), before and after:

| Link | 0.38.0 | After |
| --- | --- | --- |
| LAN | 60 | 60 |
| 20 Mbit/s, 30 ms | 59.5 | 57 (starts lower, then full rate) |
| 2 Mbit/s, 80 ms, 0.5% loss | 7.4, session dropped | 43 |
| 1 Mbit/s, 200 ms, 2% loss | 1.8, session dropped | 28 |
| 600 kbit/s, 250 ms, 1% loss | 2.4, session dropped | 25 |

With NVIDIA encoding the slow links ran at 1–7 fps before; they now switch to
the processor (below) and match the table.

## Fixed

| Priority | Finding | Fix |
| --- | --- | --- |
| High | On a slow link the viewer's health check (the host's pace figures, every 3 s, 6 s to answer) went unanswered behind video, and the session was dropped as "stopped responding" and reconnected, over and over. | The host answers at control priority; a late answer counts as a hang only if nothing at all arrived from the host meanwhile. |
| High | Automatic bitrate kept its baseline round trip from the first frame acknowledged, normally the first keyframe, which takes seconds on a slow link: congestion was then never detected and the bitrate climbed back to the full target (3.9 Mbit/s on a 600 kbit/s link). The baseline also never expired (a move to a slower route looked like congestion for good). | The base round trip is the connection's own (QUIC), its lowest of the last 30 s; keyframes no longer count as round-trip samples. |
| High | Automatic bitrate never went below 500 kbit/s (or an eighth of the target), started at the full target (a first keyframe of 200 KB at 720p), reacted only after twice the round trip plus 40 ms of queueing (seconds on a long link), and allowed at most 8 frames in flight (about 35 fps on a 250 ms link). | Floor 150 kbit/s; starts at 1.5 Mbit/s unless the round trip says local network; reacts to 60 ms (or a quarter of the round trip) of queueing, backing off to what actually got through; up to 16 frames in flight, but no more bytes than about a round trip of measured throughput. A new stream on the link (another screen, a quality change) starts at the rate the last one reached. |
| High | OpenH264's camera mode coded scrolled text almost from scratch once frames were a few a second apart (each moves far), so a slow link stayed at a few frames a second with frames of 50 KB. NVENC did the same. Its frame skipping, when on, paid a big keyframe back for many seconds of frozen picture. | Once the link holds automatic bitrate under 40% of its target, encoding switches to OpenH264's screen-content mode (scroll detection), on the processor even where a graphics card encodes; back to camera mode (sharper still text, 5x faster) after 5 s at 90%. Automatic bitrate no longer lets the encoder skip frames: the frame window holds frames back before encoding instead. |
| High | A one-time-password session cut off by the network couldn't reconnect: the host replaced the code after every session, and the viewer's automatic reconnect then failed as a wrong password. | A viewer whose link was interrupted closes it as such (no Bye); the host keeps that session's code for that viewer, once, for 150 s. The approval prompt isn't asked again for it. End-to-end test. |
| High | Unmuting sound after a while left the viewer silent for as long again (up to ~11 minutes): the host's sound restarted its packet count, and the viewer dropped everything as late until the count caught up. Meetings had the same with a microphone turned off and on. | A count far behind means a restart: playback carries on from it. |
| High (station) | Anyone could make an HTTP-only station redirect to HTTPS for good with one forged `X-Forwarded-Proto` header, taking every app offline. | Names are remembered for HTTPS only for real TLS, or the header from a proxy on the same machine or a private network; most recent first, so made-up Host names can't fill the list. |
| High (station) | Account, device and station files were replaced even when writing the new copy failed (a full disk on shared hosting): a technician's list and sign-in, a device's ID, or the whole station's setup could be lost. | All three go through the checked atomic save. |
| Medium | Every copy of up to 1 MiB of text on the viewer went to the host at once on the stream input and frame acknowledgements share, and every Ctrl+V there sent it again: on a slow link the mouse and picture froze for seconds. Over 32 MiB ended the session. | Copies up to 256 KiB go over at once; longer ones when pasted there, once; over 8 MiB is refused with a notice. |
| Medium | Copying files on a host summed them up inside the session loop: a slow or unreachable network drive held all input and video for up to a minute. | Summed up in the background (30 s at most). |
| Medium | One failed directory heartbeat cost up to 30 s plus a new hello (after a few failures over the app's life), long enough for the station to list the device offline; failed inventory uploads were retried every minute forever. | A failed heartbeat is retried once in place, and a heartbeat that gets through resets the backoff; inventory retries back off to an hour. |
| Medium | The viewer's clipboard file pastes were never cleaned up, and the host's summary (cut short on a slow drive) let it fetch more than the 64 MB / 500 files allowed. | Pastes over a day old are cleared as on the host; the limits are checked on what's really fetched. |
| Medium | Cancelling an upload still sent what was buffered (a dropped stream is finished, not reset). | Abandoned uploads reset the stream. |
| Medium | A link made while the Bridge window was minimized never opened (its result was read only while the window was drawn); likewise updates and service restarts. | Read in `logic`, which eframe runs while minimized. |
| Medium | Saving or removing in the device editor while another station call ran closed the editor and lost what was typed. | It stays open with a note. |
| Medium | "Remember" in the password prompt saved the typed password before the host accepted it: a typo replaced one that worked. | Saved once the link is made. |
| Medium (station) | A relay the hosting provider stopped wasn't restarted while hosts kept heartbeating (only hellos and admin pages checked it). | Heartbeats check it at most once a minute, after replying. |
| Medium (station) | A failing self-update was retried every 2 minutes forever, downloading again each time. | Each round of the same install waits twice as long, up to the 6-hourly check. |
| Medium (station) | App sign-in was limited per account per address: guesses spread over addresses went unchecked. | A per-account limit from anywhere as well. |
| Low–medium | Clicking beside the "Establishing link" dialog (including the window's own title bar) cancelled the connection. | Only Escape, Close or Abort. |
| Low–medium | Linux: `systemctl` ran on the UI thread every 2 s with no timeout (seconds while systemd is busy). | Looked up in the background; the window gets the last answer. |
| Low–medium | A meeting organizer's state without participants crashed a guest's window. | Nothing is drawn until there's someone. |
| Low | The Bridge copied all settings (with every station's device lists) many times a frame. | Read in place. |
| Low | GDI capture dropped a full-screen buffer on every unchanged poll; after a screen got bigger, the frame pool kept too-small buffers for good. | Both reuse their buffers. |
| Low | The relay parsed the station's whole shared device list (up to 4 MB) for every connection. | Parsed again only when the file changes. |
| Low | The port-forwarding window was shared by all links (position, fields); a refused connect request lost the window it was meant for. | One window per link; the request keeps its window. |
| Low (station) | PHP warnings could break the API's JSON on hosts that display errors. | The API never displays them (they're still logged). |

## Open

| Priority | Finding | Direction |
| --- | --- | --- |
| Medium | Keys and mouse buttons the viewer held stay pressed on the host for up to ~30 s after a silent drop (until QUIC's idle timeout). | Release held input when nothing has arrived for a few seconds while something is held. |
| Medium | The first picture on a slow link waits for a whole keyframe (about 200 KB at 720p: 3–5 s at 600 kbit/s). | Smaller first keyframes (lower resolution or quality until the link is known). |
| Medium | Windows drawn from `logic` (New link picker, device editor, prompts, Manage) pile up shapes while the window is minimized. | Draw them from `ui`; keep only polling in `logic`. |
| Medium | The viewer keeps streaming while minimized or in the tray (each frame also wakes the main window). | Don't mark a screen as drawn while its window can't be seen. |
| Medium | X11 capture keeps the screen size it started with: a resize (VM guest, xrandr) ends the session or shows part of the screen. | Follow RandR changes. |
| Medium (station) | The data folder is worked out again on every request and can switch to a new empty one; the command-line updater can pick a different one. | Keep using the folder that holds `station.json`. |
| Medium (station) | The station reports its own address from the Host header and guessed scheme; behind a TLS proxy that doesn't say so, apps can be handed `http://`. | Never downgrade the scheme on the client; a `base_url` setting. |
| Low–medium | Sound is a fixed 96 kbit/s with a 1 MiB datagram queue (seconds of stale sound after a stall); the jitter buffer is fixed. | Lower bitrate and a small datagram buffer on slow links; adaptive jitter buffer. |
| Low–medium | File transfers restart from the beginning after a drop and duplicate finished files; port forwards aren't reopened after a reconnect. | Skip files already there with the same size; reopen forwards on the same ports. |
| Low | Adaptive resolution (Speed, Low bandwidth) sends two keyframes around each pause; PipeWire drops early frames (a burst's last change can be lost); VA-API's rate control allows frames of half a second; a failed hardware encoder isn't retried during the stream. | Longer still period; keep the last frame; NVENC-like VBV and QP range; retry after a backoff. |
| Low | The saved-device list filters, groups and sorts every frame; the support report rebuilds its export every frame. | Cache by search text and a settings revision; build on Save/Copy. |
| Low (station) | Any station's Date header moves the clock used for every station's certificates; the relay's "running" check is a TCP connect only; the Rust server's rate limiter can be emptied with new device keys and its database runs on async workers. | Per-station offsets; check the relay's pid; evict old buckets; `spawn_blocking`. |

## Verification

- 257 workspace tests, including the new one-time-password resume test (and a
  check that it fails without the fix), rate-control and frame-window tests,
  and the updated clipboard test (copies over 256 KiB go over on paste).
- Strict Clippy on Linux and on the Windows target (xwin).
- Station administrator, account and HTTPS suites; forged and proxied
  `X-Forwarded-Proto` checked against the new rule.
- `scripts/test-slow-link.py` and NVENC runs as in the table above.
