# Code audit — 2026-11-05

A second whole-codebase pass, after 0.32.1 and the unreleased chat-only links:
the session engine, file tools, meetings, core/audio/codec crates, platform
backends and Android, the desktop GUI, the Windows service and app tools, and
the station (PHP, the Rust directory/relay binary and the release tool). Each
area was read by a separate reviewer; every finding below was checked against
the code before it was fixed or listed. Third-party code (vendored Opus,
generated NVENC/VA-API bindings) was treated as a dependency. The earlier
[2026-10-18 audit](AUDIT-2026-10-18.md) covers what was fixed then.

## Fixed

| Priority | Finding | Fix |
| --- | --- | --- |
| High | An unauthenticated peer could make a host allocate 32 MiB per connection with one length prefix (Hello, AuthResponse). | Messages before authentication are limited to 64 KiB on the host and 1 MiB on the viewer (`framing::read_msg_max`); file request headers to 1 MiB. |
| High | A peer that never answered the password challenge held the global sign-in throttle for 10 s at no cost, so two or three stalled connections kept real viewers out ("busy"). | The answer must arrive within 5 s, and a stalled or malformed answer counts as a failed attempt toward the lockout. |
| High | On Linux and macOS, pastes of copied files went to a fixed folder in the shared `/tmp`; another local user could replace it with a link, and the day-old cleanup then deleted folders elsewhere. | Pastes use the user's own cache folder (`~/.cache/Slipstream Remote/paste`), which must be a real folder owned by the user (mode 0700); nothing is cleaned through anything else. Cleanup runs once per paste, off the async workers. |
| High | Your own voice was garbled in every meeting recording: the recorder decoded the 2-byte sequence number in front of each Opus packet. | The recorder gets the Opus frame only. |
| High | A refused meeting join (bad token, locked, full) wrote its refusal inside the room's loop, stalling everyone's audio and video for up to 600 ms per attempt. | Refusals are sent from their own task. |
| High (Windows, to verify) | A standard user could create `%ProgramData%\Slipstream Remote` before the service was installed and keep rights to it (device key, settings) after installation. | Installing makes Administrators the owner, resets entries others added, then restricts the folder to SYSTEM and Administrators; links/junctions are refused. Needs confirmation on real Windows. |
| Medium | Chat-only links were enforced only by the viewer: a modified viewer could use files, tunnels and other tools, or set the host's clipboard, while the host showed "chat only". | The host counts any file or tool request (other than its health check), input, sound or privacy mode as viewing, telling the person there; clipboards cross only once viewing. A chat link that never controlled anything no longer releases another session's held keys. |
| Medium | A link from a web page (`slipstream://link`) could move a computer to another organisation's station without asking, overriding even a manually set station. | Outside links that would switch between private stations ask first (Bridge dialog; message box in the compact window). Links typed into the app are unchanged. |
| Medium | Switching displays reset the picture quality to what the session started with. | The viewer remembers quality changes. |
| Medium | Automatic reconnect gave up on refusals that mean "try again" (busy with another sign-in, no screen yet). | Only wrong passwords, declines and failed host verification end reconnecting. |
| Medium | A certificate for another name triggered the wrong-clock fallback, which learns the time from an unverified server: a machine-in-the-middle could shift the app's clock. | Only certificate *date* errors trigger it. |
| Medium | The Windows service's own update failed after the first one: the old program was moved to a fixed name that a signed-in user's tray app still had open. | The old program moves to a unique name, removed later by the existing cleanup. |
| Medium | Copying a large or link-cyclic folder on a host stalled its session while the clipboard summary walked it. | The walk visits each folder once and stops after 10,000 files or folders or three seconds. |
| Medium | Blocking work (drive probing, the Explorer folder query, paste folders) ran on async workers; System information requests could pile up. | These run on blocking threads; one System information collection runs at a time. |
| Medium | Meeting voice thread spun at 100% CPU after the microphone stopped (unplugged, sound server restart). | It ends instead. |
| Medium | The software H.264 encoder allocated and zeroed a whole picture every frame before using its reused planes. | The image is built from the reused planes directly. |
| Medium | The Bridge copied all settings (every station's device lists) dozens of times per frame; session and file windows redrew the 64-pixel app icon every frame. | `Client::with_settings` reads in place on the per-frame paths; the icon is drawn once. |
| Medium | On phones and narrow windows, the four device actions pushed Connect off the panel. | Below 470 points they wrap under the device name. |
| Medium | The desktop backend kept the display list from when it first opened; after docking or a resolution change, later sessions captured and mapped clicks with stale geometry. | Displays are listed afresh for each session and capture. |
| Medium (station) | Anyone with a private station's access key could fill its disk with inventory reports from fresh keys. | Inventory is accepted only from registered devices. |
| Medium (station) | New device keys cost nothing, so one address could register unlimited devices (PHP and Rust). The Rust server's rate-limit map and host log set could grow without bound. | First registrations are limited per address (`new_devices_per_minute`, 20); the Rust maps are bounded. |
| Medium (station) | Every heartbeat on a private station decoded the whole shared list to check enrollment. | A per-device marker answers the common case. |
| Medium (station) | `relay.log` grew forever. | It moves to `relay.log.1` at 32 MiB. |
| Low–medium (station) | Batched presence let one address check 60,000 IDs a minute, against 600 lookups. | Presence is also counted per ID (`presence_ids_per_minute`, 10,000). |
| Low–medium (station) | Update downloads had no size limit until checked afterwards, and the unsigned release-notes address became a link. | Downloads stop at the signed size; only `https://github.com/` release pages are linked. |
| Low | Chat panel: a superseded connection attempt kept running; the 12-chat limit could be exceeded; new messages went unnoticed while minimized; hosts refusing chat still showed an input; an automatic password re-prompt could replace one being typed in and lose the session window it belonged to. | Each fixed; chats are polled with sessions (also while minimized) and ask for attention. |
| Low | Meetings: a hostile organizer could crash a guest with an out-of-range reaction; reactions grew without bound; leaving while recording froze the window while the file was finished. | Reactions are checked and bounded; leaving finishes the recording in the background. |
| Low | Viewer: choosing a display on a chat-only link started the picture without the clipboard or sound. | One start path. |
| Low | The public station's retry delay never reset; a station change made between reading settings and waiting could be missed. | Both fixed. |
| Low | Station answers were read whole into memory. | At most 8 MiB. |
| Low | Creating folders was allowed by the browse permission rather than receive; listing a folder statted each entry twice. | Both fixed. |
| Low (station) | Admin web sign-in was limited per address only; an unchecked username became a lock-file path; concurrent update checks could collide; aborted `/relay` requests left entries behind; a new release key was briefly world-readable. | Each fixed. |
| Low | X11 capture copied every frame before comparing it with the last. | Still frames are compared in place. |

## Open

These need design work, a protocol change or real hardware to verify. They
are listed here so they are not lost.

| Priority | Finding | Direction |
| --- | --- | --- |
| High (design) | Saved device passwords are sealed with a key derived from the technician's sign-in password, and the station receives that password at sign-in. A compromised station (or its operator) could therefore open them. | Derive separate authentication and vault keys on the client and send only the former (or adopt OPAQUE); needs a station/app migration. Docs now say so. |
| Low (Windows) | Under the service, the Files window's default places (home, Desktop) and pasted clipboard files resolve to SYSTEM's own profile and temporary folder, which the signed-in user can't see. | Resolve the signed-in user's folders for defaults and pastes (as drop targets already do), while file access itself stays unrestricted. |
| Medium | Chat-only links still open the screen backend: a Wayland permission prompt can appear, and an Android phone that isn't sharing refuses the chat. | Open the backend on the first request to view. |
| Medium | Meetings: a dropped video acknowledgement can freeze a guest's camera; one shared control queue removes slow guests and lets one participant flood state updates; recordings drift at high frame rates; each frame is copied per receiver; lobby guests can send video; removal doesn't keep someone out (each join has a new key); a silent caller can hold the ringing slot; keyframe requests count toward the request limit. | See the meetings issue; each is contained but needs live room testing. |
| Medium (Windows) | DXGI capture ignores monitor rotation; the privacy curtain stays on the desktop it started on; secondary-monitor clicks use the primary monitor's mapping; DXGI reads back frames it then drops. | Needs real multi-monitor Windows machines. |
| Medium | Another user on the same machine can claim the single-instance port. | A per-user named pipe or socket. |
| Low–medium | Android: fast wheel scrolling cancels itself; JNI local references leak on the UI thread. | Needs a phone to verify. |
| Low | Long-running file tools can exhaust a session's 64 request slots, and some viewer file requests have no timeout; Windows reserved names (CON, NUL…) pass upload name checks; PowerShell errors can mix into the Explorer folder answer. | Separate limits for tunnels; timeouts; name checks. |
| Low | Stopping an encoder joins its thread on an async worker; host control writes have no timeout; clipboard polling reads full contents every 400 ms; the service log only rotates at start; one slow preview turns previews off for the session; a finished transfer can undo navigation in progress; the network scan table and X11 window shaping do work every frame; the compact window ignores chat-only/viewing changes. | Small, separate changes. |
| Low (station) | A sign-in racing a password reset can keep a token; admin Devices/Groups pages grow as devices × groups. | Issue tokens only for the verified hash; render pickers client-side. |

## By design

The Windows service serves file transfer as SYSTEM, with unrestricted access
to the whole machine: the supporting technician is meant to be able to
transfer any file. File transfer can be turned off per computer under
Config → Permissions.

## Verification

- 210 workspace tests pass, including a new end-to-end chat-only test (no
  picture or clipboard either way until viewing, the host's viewing event,
  then video), wrong-name certificate classification and outside-link
  confirmation rules.
- Strict Clippy on the Linux workspace and the Windows (xwin) app, session and
  platform crates.
- Station: PHP lint plus the administrator, relay-history, groups and account
  regression suites (`scripts/test-station-admin.py`,
  `scripts/test-station-accounts.py`), which include batched presence,
  per-device heartbeats and enrollment.
- Native Bridge screenshots at 1680 and 460 points wide.
- Not verified on real Windows: the ProgramData ownership change, the service
  update rename, the compact window's confirmation and the DXGI display refresh.
