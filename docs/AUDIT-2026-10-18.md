# Code audit — 2026-10-18

This pass reviewed the Rust session/client/server code, desktop file browser,
video and audio pipelines, Android capture/input lifecycle, and the PHP
station's authentication, account storage and download boundaries. Fixes are
included in 0.17.1. Third-party codec and graphics internals were treated as
dependencies.

## Findings fixed

| Priority | Finding and user impact | Fix and evidence |
| --- | --- | --- |
| High | Concurrent uploads shared a staging path and could fail or overwrite a completed file. Downloads with the same stem and different extensions also shared a staging path. | Unique private staging files and no-overwrite publication, with collision retries. The concurrent-upload regression failed against 0.17.0 and passes after the fix. Parallel publication and same-stem download tests verify exact bytes and separate destinations. |
| High | Stream resets and I/O failures could leave partial files behind. A declared size could be accepted before the sender actually finished. | Staging ownership removes failed/cancelled files. Receivers require the declared bytes and a clean end of stream before publishing. Reset, short and excessive-payload tests verify errors and an empty destination directory. |
| High | Disconnecting without releasing keys could leave modifiers or mouse buttons held on the cached host backend. | Every authenticated control-session exit releases input. A real encrypted-session test injects a held modifier, abruptly closes the viewer endpoint and checks the host's release event. View-only sessions do not trigger this release. |
| High | An encoder blocked on a full video queue could not observe shutdown; joining it could hang a quality change or disconnect. | Interruptible bounded queue waits. A full-queue test verifies backpressure and prompt cancellation. |
| High | A failed video writer was a detached task result; the session could remain connected with a frozen picture. | The session observes writer completion, reports the failure and tears down. A raw authenticated peer cancels its video stream and receives an explicit session-ending reason. |
| High | The decoder queue was unbounded. A slow decoder or a host ignoring frame credit could accumulate encoded video indefinitely. | Two pending frames apply asynchronous backpressure while retaining ordered H.264 decoding. Existing video/session tests exercise the changed path. |
| High | A cold Android direct connection could authenticate, then stall video and health requests after the first large send. | The failure reproduced after an app restart while a relayed cold connection worked. Disabling UDP segmentation offload on Android passed three fresh direct connections. Desktop hosts can opt into the same compatibility mode with SLIPSTREAM_DISABLE_GSO=1. |
| High | Simultaneous first starts could generate different device identities. Settings used a shared temporary filename, and concurrent saves could persist an older snapshot last. | No-overwrite identity creation, unique mode-0600 settings staging, and serialized save snapshots. Concurrent initialization/writer tests verify one identity, complete private files and agreement between memory and disk. |
| Medium | Closing a tunnel stopped its listener but left existing forwards running. Independent atomic/status updates could also report a stale active count. | Listener-owned task sets cancel live forwards; connection guards maintain counts. A session test verifies that an existing socket closes when its tunnel is dropped. Stream cancellation now also interrupts the remote splice while preserving normal half-closes. |
| Medium | IPv6 tunnel targets became ambiguous strings such as `::1:443`. Windows extended UNC paths became relative `UNC\server\share` strings. | Address/port tuples and correct UNC normalization. IPv6 loopback forwarding and UNC-path regressions cover both cases. |
| Medium | Local folder listings and shortcut discovery ran on the UI thread. Late remote listings could replace a newer navigation result. | Background listing workers, bounded filesystem concurrency, cancelled requests and generation checks. A stale-result regression verifies that old success/error replies cannot replace the current folder. |
| Medium | Opening Files from the transfer panel depended on the parent window drawing its UI. | Root logic registers both detached file windows, allowing the child action to work while the parent is minimized. |
| Medium | Clipboard and remote directory walks could follow symlink cycles indefinitely. | Shared cycle-aware local traversal and canonical-path tracking during remote walks. Tests cover both directions. Directory sorting also computes lowercase keys once per entry. |
| Medium | Transfers read until EOF after advertising a fixed length, so a growing source could send extra data; special files could block or produce unbounded data. | Send exactly the advertised length, fail on premature EOF, and reject non-regular sources. Receivers reject extra payload bytes. |
| Medium | Update downloads accepted unlimited trailing data, left staging files after failures and read the whole executable back into memory for verification. The write probe could overwrite a same-named file. | Stream the signed-prefix hash; bound the trailer to the existing 64 KB config allowance; add response/idle deadlines and private staging cleanup. Use a unique write probe. Loopback HTTP tests cover valid provisioning, corruption, oversized headers and oversized bodies without Content-Length. |
| Medium | Android's frame-rate limiter acquired and discarded early images, including the final image of a screen that had become still. Readers could be closed during a native frame copy. | Schedule a drain of the newest image at the next capture interval; close replaced readers on the same frame worker that owns image acquisition/JNI copies. |
| Medium | A stalled audio backend could block initialization or shutdown indefinitely. | Bound startup and worker joins. Simulated stalled-driver tests cover both phases without touching system audio. A worker stuck inside a driver finishes in the background when that driver returns. |
| Medium | A viewer could acknowledge an unissued frame number and underflow frame-credit accounting. | Ignore acknowledgements beyond the last issued sequence. The credit test includes future and maximum-u64 values. |
| Medium | The Rust server trusted the leftmost forwarded address behind a local reverse proxy, allowing a client-supplied prefix to change the rate-limit bucket. | Trust the last address appended by the immediate local proxy, including repeated header fields; ignore forwarding from direct non-loopback peers. Regression tests cover spoofed prefixes and malformed suffixes. The PHP station continues to use REMOTE_ADDR. |
| Low | Frame serial numbers and image pixels could be read from different publications; repaint callbacks ran under a lock and could deadlock on reentry. | Publish/read serials and pixels under the same lock, invoke cloned callbacks after unlocking, and stress-test matching frame/serial pairs and callback reentry. |
| Low | Raw-frame/foreign PipeWire bounds used overflowing u32 arithmetic. Extreme signed registration timestamps could overflow subtraction/absolute value. | Checked/widened buffer bounds before making foreign slices; unsigned absolute timestamp differences. Tests include maximum dimensions, negative/short strides, truncated chunks and extreme timestamps. |

The reverse-proxy fix follows the documented single-local-proxy model:
NGINX appends its peer address after incoming forwarding values. See the
[NGINX proxy variable documentation](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#variables).
Deployments with multiple trusted proxy hops need an explicit trust policy.

The Android transport mitigation matches the fallback failure described in
[Iroh issue 4555](https://github.com/n0-computer/iroh/issues/4555). It sends
individual datagrams on Android; other platforms retain offload by default.

## Verification

- 115 workspace tests pass, with five opt-in tests ignored, including real local encrypted sessions, filesystem races,
  interrupted transfers, tunnel closure, IPv6 forwarding and HTTP update bodies.
- Linux and Windows Clippy checks include all targets and test code; Android
  checks compile the arm64 host implementation. The broader Windows check also
  caught and repaired an outdated cursor-test call.
- An isolated X11 GUI check verified exact desktop-drop bytes, opening the Files
  window from its receipt while the parent was hidden, and both asynchronous
  panes navigating to test directories. Android cold-start checks used an
  Android 16 emulator, followed by revocation/regrant and full PC control,
  typing, held-touch dragging, rotation and Stop-notification checks.
  Production settings and remote machines are not test fixtures.

## Remaining limits

Input state is shared between simultaneous controllers; ReleaseAll remains a
global backend operation. Independent controller ownership needs a separate
interaction design. A permanently blocked audio driver can retain its detached
worker until process exit; a cancellable audio backend would reclaim it sooner.
An abrupt process kill can leave hidden staging data; handled failures and
ordinary cancellation clean it up.
Physical Windows, macOS and Android hardware still need runtime confirmation.
This pass does not replace fuzzing, load testing or a dependency-advisory audit.
